# Dar Zellij — notes for Claude

One-page website **proposal** for Restaurant Dar Zellij (Marrakech Riads, 17th-century riad in the Marrakech medina), to show the owner as a new version of https://marrakech-riads.com/restaurant-dar-zellij/. Made in the spirit of the user's Farasha Farmhouse proposal (`C:\Users\pakiy\Documents\prj\Farasha`, same motion vocabulary). Static site, no backend: the booking form is frontend only. The live page still exists, so this demo is **noindex** (see README "Before launch").

## Stack and commands

- Next.js 16 (App Router, Turbopack) + React 19 + TypeScript strict + Tailwind 4 (`@tailwindcss/postcss`, reset only; styling is hand-written in `src/styles/globals.css`). **Read `node_modules/next/dist/docs/` before using a Next API**: `proxy.ts` replaced middleware, `params` are Promises, `PageProps`/`LayoutProps` are global types (`npx next typegen`).
- Motion: GSAP 3.15 (ScrollTrigger, SplitText) via `@gsap/react`, Lenis 1.3. Fonts via `next/font/google`: Cormorant (headings, prices), Tenor Sans (small caps), Jost (text).
- npm. `npm run dev` / `build` / `start` / `typecheck` / `format` / `photos:import` / `images` / `icons`.
- `.claude/launch.json` (git-ignored): `preview` = production server on port 3100 (`npm run build` first), `dev` on 3000.
- Git: `main` on github.com/P4kiya/dar-zellij (private). Commit and push only when the user asks. `npm run format:check` passes; `tsconfig.json` is in `.prettierignore` because Next rewrites it on every build.

## Layout

- Routes: `src/app/[lang]/layout.tsx` (root layout: fonts, metadata, head script, preloader, brand SVG symbols) and `page.tsx`; `dynamicParams = false`, `/fr` and `/en` prerendered. `src/proxy.ts` redirects `/` by Accept-Language (French default). `src/app/global-not-found.tsx` (+ `experimental.globalNotFound`) handles other URLs.
- Copy: `src/content/fr.ts` (source of the `Dictionary` type) and `en.ts`; light markup `*italic*`, `^sup^` rendered by `components/rich.tsx`. Menu and prices: `src/content/menu.ts` (from the owner's Sept 2024 PDFs; per-language wording kept where the PDFs differ; an empty string means "not in this language"). Alt text: `src/content/photos.ts`. Facts, hours, contacts: `src/lib/site.ts`.
- Sections in `src/sections/` are **server components**; interactive parts are client components next to them (`riad-rooms`, `ritual-scroller`, `menu-book`, `week-grid`, `gallery-grid`, `booking-form`, `date-picker`, `curtain-reveal`). Client components receive only the strings they need as props.
- The booking form's date field is a button plus a calendar `<dialog>` (`sections/date-picker.tsx`), not an `<input type="date">`: the browser's picker (blue, system font, the visitor's date order) looked foreign and the user asked for one in the site's style. It follows the WAI-ARIA date picker dialog pattern (`role="grid"` table, one `td` with tabindex 0, arrows/Home/End/PageUp/PageDown, Enter picks, Escape closes and refocuses the field). Non-modal `show()` popover from 768px; `showModal()` sheet below (`MEDIA.mobile`, the same query as the CSS phone block) because a fixed sheet inside the panel would be trapped by RevealText's leftover `transform: translate(0, 0)`; the top layer escapes it. Its content is only rendered after the first open (its "today" is only known in the browser). Past days and Tuesdays are `aria-disabled`; the focus is clamped to today, so the previous-month arrow is `aria-disabled` on the current month. Days are YYYY-MM-DD strings handled at noon UTC.
- The hero is the photograph, the DAR ZELLIJ lettering (as the h1, with visually hidden text) and one line: the user found the previous version (eyebrow, big serif title, tagline, two buttons, hours, status, scroll cue) "too much text, looks AI generated". Keep it that bare. The header hides its own lettering until the page is scrolled, so the name is not shown twice.
- Photos: `src/lib/photos.ts` is `server-only` (it imports the generated `photos.json` manifest). Client components get `PhotoData` from the server and render `components/photo-img.tsx`; client-safe types/helpers are in `lib/photo-data.ts`. Server `Photo` (`components/photo.tsx`) = frame + placeholder + RevealImage.
- Brand marks: `components/brand.tsx` holds the rosette, the DAR ZELLIJ lettering and the ornaments of the menu's inner pages (flower, rule band, corner sprig), traced from the menu PDF (potrace; the ornaments reduced to straight edges), rendered once as `<symbol>`s and used with `<use>`. `scripts/build-icons.mjs` reads the rosette path from that file.

## The menu book (`sections/menu-pages.ts` + `menu.tsx` + `menu-book.tsx`)

The menu is a 3D book, not PDFs (the user: "the pdf is a old thing"; the PDFs were removed from `public/`). `menu-pages.ts` lays out 28 pages from `content/menu.ts`: cover, endpaper, title page, 23 pages (starters ×2, mains ×2, signature dishes, desserts, 3 set menus, drinks title page, cocktails ×5, wines ×4, aperitifs/spirits/softs/hot drinks ×4), endpaper, back cover. The page count must stay **even** (leaves are pairs; the last leaf is the back cover). `menu.tsx` renders them, `menu-book.tsx` turns them.

- **The pages are HTML strings** (`dangerouslySetInnerHTML`, text through `esc()`/`richHtml()` from `components/rich.tsx`, marks through `markHtml()` from `components/brand.tsx`), on purpose: as React elements the 28 pages (≈1,200 elements) were hydrated on load and cost a slow phone ~350 ms of main-thread time (Lighthouse mobile 56 instead of ~70). The App Router hydrates everything it rendered, server components included, so moving them out of the client component did not help; only markup React does not walk does. The client component is not the pages' parent either: it finds the server-rendered `.menu-book__stage` through its own parent element and drives it by hand.

- **Sizing:** everything in the book is in `--u` = 1% of a page's width (`--page-w`, rounded to whole pixels), so pagination is the same at every size. Pages must not overflow: the fullest page is at 93% (EN "Mains (continued)"). After changing content, measure (a puppeteer script that compares each `.bk-body`'s content height with its height, in both languages, at phone and desktop widths) or at least look at every page on a phone.
- **Model:** a leaf = `[front, back]` page indexes on two pages (≥ 860 px, `SPREAD` in the tsx, the same media query in the CSS), `[page]` on one page (endpapers skipped). `pos` = number of leaves turned; max is `leaves.length` on two pages (closed on its back) and `leaves.length − 1` on one. Angles live in a ref and are written to `--a` on both faces by GSAP; back faces get `rotateY(-a) translateX(100%) rotateY(180deg)`, so no z-index changes are ever needed (fronts `--n − --i`, backs `--i`). Only pages near the open ones are `is-live` (display: block); the rest are `display: none` and, once hydrated, `inert`.
- **Sharp text:** while the book is open and nothing moves (`is-resting`), the body and pages have no 3D transform and no perspective, so the text is drawn on the pixel grid. Any drag or turn removes the class. Don't add a rest tilt.
- **Shade:** each page's last child is `.bk-shade`; the script sets its opacity (a registered non-inherited custom property does not reach a pseudo-element, which is how the first version silently showed nothing). `--on-left/--on-right` on the body drive the shadows and edges of each half, so an empty half never shows a shadow (it read as a blank sheet).
- **Controls:** never `disabled` on the "next" arrow (a focused button that becomes disabled drops the keyboard focus); it is `aria-disabled`. When the controls swap (closed ↔ open) the focus is handed to the replacement. The status line is always in the DOM (`aria-live`).
- **Touch:** `touch-action: pan-y pinch-zoom` on the leaves; a sideways drag turns, vertical scroll and pinch stay native.

## Photos

- `scripts/import-photos.mjs` downloads originals from marrakech-riads.com into `.cache/originals` (git-ignored) and writes masters to `public/images`: the 2023 triptychs are split at their seams (listed in the script); 2018 HDR photos get `grade: 'calm'`; hero masters use lower quality (80/76). `scripts/build-images.mjs` makes 400/800/1200/1600 copies, `src/lib/photos.json` (size, average colour, 16px blur) and `public/og.jpg`.
- `sizes` must reflect the _drawn_ width: with `object-fit: cover` in tall frames a landscape photo is drawn much wider than the screen (rooftop `350vw` on phones, closing `400vw`, hero portrait `150vw`). Getting this wrong made phones load the 400 px copy (blurry).
- Photos are cached a year as immutable (next.config headers): a replaced photo needs a new name once deployed.

## Motion system (gotchas)

- `useMotion(setup, scope, deps, defer?)` = useGSAP + gsap.matchMedia with `{ reduced, mobile, desktop }` (`desktop` = ≥1024px wide and ≥600px tall, for pinning). `defer` (e.g. `belowFold`) waits for fonts + idle.
- **The hero and the preloader are pure CSS** (keyframes in globals.css, delays via `--d` and `--intro`): the head script adds `has-preloader is-preloading` on the first view of a session and sets the sessionStorage flag; `preloader.tsx` only removes the finished preloader (at 2.75s). This was done for LCP: Chrome excludes full-viewport hero images from LCP, so LCP is the hero text, and it must not wait for hydration. Don't move the hero back to JS reveals.
- Never put a CSS `transition` on a property GSAP animates on the same element (the ritual beats ended at opacity 0 on phones because of this). Ritual beats are dimmed with `color` in the scroll-driven mode.
- Background morph (`use-background-morph.ts`) only blends the **light** sections (`data-bg` ivory/sand). Dark sections (ritual, week, gallery) and photo sections keep solid backgrounds; blending light into dark left outgoing text on the wrong colour.
- SplitText headings get `.is-split` (flex column so line masks don't collapse); don't reintroduce a universal `:has()` selector (expensive style recalcs).
- `.photo-frame` base rules are wrapped in `:where()` so section classes can position frames (otherwise `position: relative` overrode `.rooftop-photo { position: absolute }` and the photo vanished).
- Tailwind 4 ships a `container` utility: the layout class is `container-dz`.
- The phone menu is `position: fixed` inside the header: the header must not have `transform` or `backdrop-filter` while open (`.nav-shell.is-open` removes the blur).

## Verification approach

- The app's Browser pane is often hidden (scroll animations don't fire there). Use headless Edge from the session scratchpad: `puppeteer-core` + `sharp` (+ `axe-core`, `lighthouse`) installed there, `C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`, production server on 3100, scroll in steps before screenshots, set `sessionStorage['darzellij:preloaded']='1'` via `evaluateOnNewDocument` to skip the preloader.
- Last results (30 Sep 2026, local `next start`, HTTP/1.1): Lighthouse FR mobile 56–64 (noisy machine; TBT 350–620 ms) / desktop 94, accessibility 100, best practices 100, SEO 69 only because of noindex; axe-core 0 violations (FR desktop, EN phone). Real Edge with 4× CPU throttle: LCP = the hero lettering at ≈ 0.7s (return visit), ≈ 2.1s (first visit, behind the preloader). Lighthouse's simulated mobile LCP stays ~6.8s whatever the hero does: Lantern chains the first paint behind the inline RSC payload scripts. The live page scored mobile 23 / desktop 52 / accessibility 84 with the same setup.
- **LCP lessons** (measured, not guessed): an inline `<svg>` is never an LCP candidate; an `<img>` painted at opacity 0 first, or clipped away by a mask at its first paint, is never counted later; `decoding="sync"` on an SVG `<img>` held its paint back by a second; an image whose first paint is a frame later than FCP gets chained behind hydration in Lantern. So the hero lettering is an `<img src="/wordmark.svg">` (written by `scripts/build-icons.mjs`), fading from opacity 0.02 with no delay and without waiting for `--intro`.
- Windows Defender sometimes makes one `next build` take ~12 min; it's normally ~20s.
